# Siyagah — project rules

**PERMANENT RULE: Project Control File.** The owner keeps one shared Project
Control File (PCF) for all projects: https://claude.ai/artifact/PhW1KKX28qrqj9dE7Ha8dZ.
Siyagah's section is SIY (database `p/siy`, `p/siy/jobs`, `p/siy/guides`; write
nothing outside it). Every session reads it first and updates it before finishing. Nothing is reported as done unless it is recorded
there. The live page is the record; these rules are copied here so they survive
outside it. Where this file and the PCF disagree, the PCF wins.

## Standard rules (the shared file's general rules, R1–R13; kept here as a copy)

1. **Project Control File:** this file is our Project Control File. It holds the
   jobs, monitoring, follow-ups, status and project information, and both of us
   can read and edit it (unlike Claude's memory). Every Claude delivery comes with
   an updated copy, and it carries forward to each new session. Work in the live
   file in the Claude app; downloaded copies (named "Siyagah - PCF vXX.YY -
   YYYY-MM-DD.html") are offline backups that Claude can't see.
2. Every session starts by reading this file and ends by updating it. Nothing is
   reported as done unless it's recorded here.
3. Jobs are for once; rules are for always. Standing instructions live here, not
   in the job list.
4. **Spend approval:** Claude always asks before any paid run (paid APIs, credits,
   paid services) and never spends money without confirmation.
5. **Creative and design choices:** Claude offers 2–3 options or a short plan
   before finalising, rather than deciding alone.
6. **Long sessions:** Claude flags when a session is getting too long, summarises
   the state here, and gets approval before moving to a new session.
7. **File naming:** "<Project> - <TYPE> vXX.YY - YYYY-MM-DD", moving the version
   forward with each delivery.
8. **Purpose:** keep every plan and job in one place so nothing gets lost or
   skipped between sessions.
9. **Goal:** this should reduce the owner's time spent, not create more work for
   them.
10. **Visual rules:** colour and tick show each job's status at a glance. Jobs
    needing the owner stand out; finished jobs are dimmed and hidden. Any line can
    be dimmed or hidden but stays available.
11. Use this same template for every project and app build.
12. **Time-saver:** the owner can answer the Your-turn list in one chat message
    (for example "J01 done, J02 A"); Claude updates the file from that.
13. **Change tracking:** anything the owner adds or changes is marked "New" and
    listed under What's new. When Claude reads the file it replies under each
    change, clears the New marks, and stamps "Claude last checked". Claude checks
    at the start of every chat reply and in a scheduled check every 4 hours.

## Siyagah: decided by the owner

- One user, one Google account. No sharing, no second person's notes. (D1)
- No note, folder or section is ever lost or silently changed. The one exception
  is a deletion the owner makes, which still goes through Trash. (I1, D2, D3)
- A change on one device reaches the others by itself; it works offline and
  installed, and a new version really arrives; a downloaded copy still opens years
  from now with its notes. (I2–I4, D2)
- Every feature ships on phone, tablet and laptop in the same round. (D5)
- A folder that still holds notes cannot be deleted; deleting an empty folder must
  sync. (D6)
- The Architect puts a green, checked round live without asking. (D7)
- A round the Architect built itself may be merged by the Architect, but only after a
  FULL RECHECK on the exact commit. (D8, PCF J06, 12 Oct 2026)
- Jobs can arrive scattered; Claude writes the owner's words down first, then
  splits and orders the work.
- Reports to the owner use plain words, say what was not done and why, and ask for
  at most two checks.
